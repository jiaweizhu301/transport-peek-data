TransportPeek — Privacy Policy

Last updated: 2026-09-22

Summary

TransportPeek shows public transport departure times for Sydney. It has no accounts, no sign-in, and no user profiles. We do not collect, store, or sell personal information.

What stays on your device

  • Your saved favourites (a stop plus a direction, or a stop-to-stop trip).
  • App settings: language, theme, Wi-Fi-only downloads, refresh interval.
  • The downloaded offline timetable database.

All of the above is stored locally. Favourites and settings may be included in your device's own Android backup if you have that enabled; the timetable database is excluded from backup because it can be re-downloaded.

What leaves your device

  • Real-time requests. When you view a stop, the app asks our service for live departures for that stop. The request contains the stop identifier and the transport mode. It does not contain your name, account, contacts, or precise location.
  • Timetable and configuration downloads. The app downloads timetable files and a configuration file from GitHub Releases. GitHub acts as the file host.

Our service keeps short-lived operational data (which stops were recently requested, and a cache of live departures) so it can refresh upstream data efficiently. This data is not linked to a person and is overwritten continuously.

Location

The app can use your location to list stops near you. This is optional: the feature only asks for permission when you tap "Find stops near me", and everything else in the app works without it.

When you use it, your location is read only while the app is open and is used only on your device, to measure how far each stop is from you. It is never sent to our service, to Google, or to anyone else; it is not stored on the device and does not appear in any log or analytics event.

The app does not request background location permission, and it never tracks where you are over time.

Advertising

The current release shows no ads at all (ads.enabled = false). However, the Google AdMob SDK is bundled and is started when the app launches, so it can read the advertising ID even though no ad is displayed. If ads are ever switched on, this page will be updated first, and users in the EEA, the UK and Switzerland will be shown a consent prompt before any personalised advertising.

Advertising ID

The app's merged manifest includes com.google.android.gms.permission.AD_ID and android.permission.ACCESS_ADSERVICES_AD_ID, brought in by the AdMob SDK. The advertising ID is a resettable device identifier. It is not your name or an account, but it is not anonymous either — so this page does not describe our data as "anonymous"; it says only that data is not linked to your name or to an account.

Usage statistics

The app reports five Firebase Analytics events, and nothing else:

  • app_session_start — a foreground session begins (parameter: how it was opened).
  • app_session_end — that session ends (parameter: its length in seconds).
  • stop_detail_open — a departure detail screen was opened.
  • widget_bound — a home-screen widget was linked to a favourite (parameter: its size).
  • widget_bg_refresh — a background widget refresh ran (parameters: whether the screen was on, and whether a network request was made).

These events carry no stop names, no favourites, no search terms and no location. Firebase Analytics also collects the advertising ID by default (see above).

Crash reports

Firebase Crashlytics collects crash stack traces plus device model, OS version, app version and session timing. It does not collect your favourites or anything you searched for.

Children

The app is not directed at children and does not knowingly collect data from them.

Data sources

Timetable and real-time data come from Transport for NSW under CC BY 4.0. See the attribution page.

TransportPeek — 隐私政策

最后更新：2026-09-22

一句话

TransportPeek 显示悉尼公共交通的发车时间。没有账号、不需要登录、不建用户画像， 不收集、不保存、不出售个人信息。

只留在你手机上的

  • 你的收藏（站 + 方向，或者站 A → 站 B）。
  • 应用设置：语言、主题、仅 Wi-Fi 下载、刷新间隔。
  • 下载下来的离线时刻表数据库。

以上全部存在本机。收藏与设置可能会进入安卓自带的备份（如果你开了备份）； 时刻表数据库不进备份，因为它随时可以重新下载。

会离开你手机的

  • 实时查询。你打开某个站时，应用会向我们的服务请求该站的实时发车。 请求里只有站点标识和交通模式，不含姓名、账号、通讯录或精确定位。
  • 时刻表与配置下载。应用从 GitHub Releases 下载时刻表文件与配置文件， GitHub 只作为文件托管方。

我们的服务会保留很短期的运行数据（最近被请求过哪些站、实时发车的缓存）， 用于高效刷新上游数据。这些数据不与任何个人关联，并会被持续覆盖。

定位

应用可以用你的位置列出附近的车站。这是可选的：只有你点了「用定位找附近的站」 才会请求权限，app 的其他功能不需要它也能正常用。

用到的时候，位置只在 app 打开时读取，而且只在你的手机上使用， 用来算每个车站离你多远。它不会发给我们的服务、不会发给 Google、也不会发给任何其他人； 不会存在手机上，也不会出现在任何日志或统计事件里。

应用不申请后台定位权限，也不会持续记录你的行踪。

广告

当前版本一个广告都不展示（ads.enabled = false）。 但 Google AdMob SDK 随 app 一起打包，并在启动时初始化，因此即使不展示广告， 它也可能读取广告 ID。若将来真的开启广告，会先更新本页；欧洲经济区、英国、瑞士的用户 在出现个性化广告前会先看到同意弹窗。

广告 ID

合并后的权限清单里有 com.google.android.gms.permission.AD_ID 与 android.permission.ACCESS_ADSERVICES_AD_ID，由 AdMob SDK 带入。 广告 ID 是可重置的设备标识符，不是姓名也不是账号，但它也不等于「匿名」—— 所以本页不再使用「匿名」这个说法，只说这些数据不与你的姓名或账号关联。

使用统计

应用只上报以下 5 个 Firebase Analytics 事件，没有别的：

  • app_session_start —— 一次前台会话开始（参数：从哪里打开的）。
  • app_session_end —— 这次会话结束（参数：时长秒数）。
  • stop_detail_open —— 打开了某条收藏的详情页。
  • widget_bound —— 桌面小组件绑定到某条收藏（参数：尺寸）。
  • widget_bg_refresh —— 后台刷新跑了一次（参数：当时是否亮屏、这次有没有发请求）。

这些事件不含站名、不含收藏内容、不含搜索词、不含位置。 另外 Firebase Analytics 默认会采集广告 ID（见上一节）。

崩溃报告

Firebase Crashlytics 采集崩溃堆栈，以及机型、系统版本、app 版本与会话时间。 它不采集你的收藏，也不采集你搜索过什么。

儿童

本应用不面向儿童，也不会有意收集儿童数据。

数据来源

时刻表与实时数据来自 Transport for NSW，按 CC BY 4.0 授权使用， 见归属页。
